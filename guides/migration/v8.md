# Migrating to v8 and the 2026-10 Pinecone API

v8 moves the SDK to Pinecone API version `2026-10`, which adds replica autoscaling for dedicated
read capacity and reports indexes, collections, backups, and restore jobs that use features
`2026-10` can't represent. The `X-Pinecone-Api-Version` header is sent as `2026-10` on every
request.

For most code, the only change is the import path, and nothing deprecated in v7 is removed. Two
rare patterns no longer compile:

- A struct literal that leaves out the field names, for a struct that gained fields, such as
  `pinecone.PineconeError{403, err}`. Name the fields.
- Comparing `SupportedParameterValue` values with `==`, or using one as a map key. It gained a
  `RawValue` field of type `json.RawMessage`, so compare the fields you need instead.

Everything under [Behavior changes](#behavior-changes) compiles unchanged, so the compiler won't
point you to it. If you use dedicated read capacity, read
[Describing an autoscaled index](#describing-an-autoscaled-index) and
[Server errors follow 2026-10](#server-errors-follow-2026-10) first. If you page through lists,
read [The last page of a list has a nil token](#the-last-page-of-a-list-has-a-nil-token).

## Update the import path

```sh
go get github.com/pinecone-io/go-pinecone/v8/pinecone@latest
```

Then replace `go-pinecone/v7/` with `go-pinecone/v8/` in your imports:

```sh
grep -rl 'go-pinecone/v7/' --include='*.go' . | xargs sed -i '' 's#go-pinecone/v7/#go-pinecone/v8/#g'
```

On Linux, use `sed -i` without the empty `''`. Then run `go mod tidy` to drop the `/v7` requirement
from `go.mod`.

## What's new: replica autoscaling

Set `Scaling.Auto` on `ReadCapacityDedicatedConfig` to let Pinecone move the number of replicas per
shard between `MinReplicas` and `MaxReplicas`. It works on every create method and on
`ConfigureIndex`. See [Replica autoscaling](../index-management/indexes.md#replica-autoscaling).

Replica autoscaling is in private preview. Only organizations Pinecone has enabled can use it;
for any other organization, a request with `Scaling.Auto` fails with the error code `FORBIDDEN`.
Contact [Pinecone support](https://support.pinecone.io) to ask about access.

New in v8, all additions:

- `ReadCapacityDedicatedConfig.Shards` and `ReadCapacityDedicated.Shards`
- `ReadCapacityScaling.Auto` and `ReadCapacityAutoScaling{MinReplicas, MaxReplicas}`
- `ReadCapacityDedicated.ScalingStrategy`, with `ReadCapacityScalingStrategyManual` and
  `ReadCapacityScalingStrategyAuto`
- `Client.ListIncompatibleIndexes` and `IncompatibleIndex`, for indexes that use a feature
  `2026-10` can't represent. Each entry's `MinimumAPIVersion` is the earliest generally available
  API version that can describe the index (every later one can too), and `PreviewAPIVersion` is the
  earliest early-access one; either is `nil` when there's no such version. `ListIndexes` leaves
  those indexes out, and `DescribeIndex` refuses them with the error code `FAILED_PRECONDITION` and
  the reason `RESOURCE_INCOMPATIBLE_WITH_API_VERSION`, and its `PineconeError.Details()` carries
  the same versions. See
  [List indexes](../index-management/indexes.md#list-indexes).
- The same for collections, backups, and restore jobs: `Client.ListIncompatibleCollections` and
  `IncompatibleCollection`, `BackupList.IncompatibleData` and `IncompatibleBackup`, and
  `RestoreJobList.IncompatibleData` and `IncompatibleRestoreJob`. See
  [Collections](../index-management/collections.md#list-collections) and
  [Backups](../index-management/backups.md#describe-list-and-delete-backups).
- `PineconeError.ErrorCode`, `PineconeError.Reason`, `PineconeError.Message`, and
  `PineconeError.Details()`, read from the API's error response. Branch on `ErrorCode`, and on
  `Reason` when the API sets one; `Code` is still the HTTP status. Pinecone is adding reasons and
  details endpoint by endpoint, so many errors don't set `Reason` or details yet: treat both as
  optional and fall back to `ErrorCode`. `Msg` gains a `"reason"` key when the API sends one; see
  [Error text changes](#error-text-changes) for its other changes.
- `PineconeError.TypedDetails()`, which returns the documented `details` keys as typed fields in an
  `ErrorDetails`.
- Reason constants: `ReasonResourceIncompatibleWithAPIVersion`, for a resource that uses a feature
  `2026-10` can't represent, and `ReasonTooManyDocuments`, `ReasonRateLimitExceeded`, and
  `ReasonMonthlyLimitExceeded` for document requests. See
  [Request limits](../data-operations/documents.md#request-limits).
- `ModelInfo.Modalities`, the kinds of input a hosted model accepts (`"text"`, `"image"`, `"pdf"`),
  and `ListModelsParams.Modality`, which lists only the models that accept one of them. See
  [Hosted models](../inference/inference-api.md#hosted-models).
- `User.Accounts` and `UserAccount{Type, NameId}`: the accounts an admin API user can log in with,
  when the organization has an SSO connection. See [Users](../admin.md#users).
- `Import.ValidationResult` and `ImportValidationResult{ImportSuccesses, ImportErrors}`: how many
  records of a bulk import passed and failed validation. See
  [Check an import](../data-operations/bulk-import.md#check-an-import).
- `SupportedParameterValue.RawValue`: the JSON text of a model parameter's allowed or default
  value when no typed field can hold it exactly, such as an array, an object, or an integer outside
  the `int32` range. `ListModels` and `DescribeModel` used to fail on an array or object value.
  v7 decoded an integer outside the `int32` range into a rounded `FloatValue`, which v8 still sets
  alongside the exact `RawValue`. See [Hosted models](../inference/inference-api.md#hosted-models).
- `SearchRecordsResponse.Namespace`: the namespace that served a legacy Records API search. See
  [Search records](../inference/integrated-embedding.md#search-records-legacy-records-api).

## Behavior changes

These don't change any signature, but code that relies on the old behavior may need an update.

### List calls can leave items out

An index that uses a feature `2026-10` can't represent isn't returned by `ListIndexes`; there's no
error. Code that counts or inventories indexes should also call `ListIncompatibleIndexes`.
`DescribeIndex`, `ConfigureIndex`, `CreateCollection`, and `CreateBackup` refuse such an index with
the error code `FAILED_PRECONDITION` and the reason `RESOURCE_INCOMPATIBLE_WITH_API_VERSION`.

The same goes for other resources. `ListCollections` leaves such a collection out (list it with
`ListIncompatibleCollections`). `ListBackups` and `ListRestoreJobs` move such an item from `Data`
to `IncompatibleData`, and it still counts toward `Limit`, so a page can hold fewer than `Limit`
items in `Data` while `Pagination` points to more.
`DescribeCollection`, `DescribeBackup`, `CreateIndexFromBackup`, and `DescribeRestoreJob` refuse
such an item with the same error code and reason.

### Describing an autoscaled index

For an autoscaled index, `ReadCapacity.Dedicated.Scaling.Manual` is nil and `Scaling.Auto` holds
the bounds. v7, on API version `2026-07`, reported such an index as manually scaled, with
`Scaling.Manual.Replicas` set to the live replica count, and the API refuses a v7 change to its
replicas or shards with the error code `INVALID_ARGUMENT`. Code that reads `Scaling.Manual.Replicas`
without a nil check panics on such an index, including one created from the console or another
SDK. Check `ScalingStrategy` (a pointer, nil when the API reports no strategy), or `Scaling.Manual`
for nil, first. The live number of replicas per shard is in `Status.CurrentReplicas`.

`ReadCapacity.Dedicated.Scaling` is nil when the SDK doesn't recognize the strategy;
`ScalingStrategy` still reports its name.

### Shards moved out of the manual scaling block

`ReadCapacityManualScaling.Shards` is deprecated. Use `ReadCapacityDedicatedConfig.Shards` on
requests and `ReadCapacityDedicated.Shards` on responses. The old field still works:

- On requests, it's sent as `Shards` when `Shards` isn't set. When both are set, `Shards` wins and
  the deprecated value is ignored, so a scaling block copied from a describe response doesn't undo a
  shard change.
- When you describe a manually scaled index, it's still filled in.

### Deprecated vector fields count integrated embedding

The deprecated `Index.VectorType`, `Index.Dimension`, and `Index.Metric` now treat a `StringField`
with `Embed` as the index's dense vectors and a `StringField` with `SparseEmbed` as its sparse
vectors; `Backup.Dimension` and `Backup.Metric` also come from a `StringField` with `Embed`. v7
looked only at vector fields. For a document index with integrated embedding:

- With `Embed`, `VectorType` is `"dense"`, and `Dimension` and `Metric` come from the `Embed`
  config. v7 left them empty, or reported `"sparse"` and `dotproduct` when the index also had a
  sparse field.
- With only `SparseEmbed`, `VectorType` is `"sparse"` and `Metric` is `dotproduct`. v7 left them
  empty.
- With more than one dense field, all three stay empty even when the index also has a sparse field.
  v7 reported `"sparse"` in that case.

These fields were deprecated in v7. Read `Schema` and `Deployment` instead:

| Deprecated | Read instead |
|---|---|
| `Index.Dimension`, `Index.Metric` | `Dimension` and `Metric` of the index's `DenseVector` field (named `_values` in an index created from a dimension and metric), or of the `Embed` config of a `String` field |
| `Index.VectorType` | Which kinds of field `Schema.Fields` holds: `DenseVector` or `String.Embed` for dense vectors, `SparseVector` or `String.SparseEmbed` for sparse ones |
| `Index.Spec.Serverless`, `Index.Spec.BYOC`, `Index.Spec.Pod` | `Index.Deployment.Managed`, `Index.Deployment.Byoc`, `Index.Deployment.Pod`; read capacity is in `Index.ReadCapacity` |
| `Index.Embed` | The `SemanticText` field in `Schema.Fields` of a legacy integrated index |

```go
// v7
dimension := *idx.Dimension
region := idx.Spec.Serverless.Region
// v8
if f, ok := idx.Schema.Fields["_values"]; ok && f.DenseVector != nil {
	dimension = f.DenseVector.Dimension
}
if idx.Deployment != nil && idx.Deployment.Managed != nil {
	region = idx.Deployment.Managed.Region
}
```

### `ModelInfo.Modality` is deprecated

API version `2026-10` reports a list, `Modalities`, instead of a single `modality`. `Modality` is
deprecated and still works: the SDK fills it from `Modalities`, with `"text"` for a model that
accepts text, as earlier API versions report for a model that also accepts other input. For a
model that accepts one kind of input, it's that kind. For a model that accepts several kinds of
input but not text, `Modality` is nil.

```go
// v7
fmt.Println(*model.Modality)
// v8
if model.Modalities != nil {
	fmt.Println(*model.Modalities)
}
```

### An empty `Scaling.Manual` block is an error

`ConfigureIndex` with a `Scaling.Manual` block that sets neither `Replicas` nor `Shards` now
returns an error without sending the configure request. v7 sent `"manual": {}`. API version
`2026-10` requires a replica count with manual scaling, and sending 0 would pause the index. Set
`Replicas`; to change only the shard count, set `ReadCapacityDedicatedConfig.Shards`; to keep the
current scaling, leave `Scaling` out. The create methods return the incomplete read capacity
error below for an empty `Scaling.Manual` block, as in v7.

### More requests are checked before they're sent

These calls now return an error without calling the API, where v7 sent the request:

- `DescribeIndex`, `DeleteIndex`, and `ConfigureIndex` with an empty index name.
- `Organization.Describe`, `Organization.Update`, and `Organization.Delete` on the `AdminClient`
  with an empty organization ID.
- `Invite.Create` on the `AdminClient` with no `RoleBindings`.
- `DescribeCollection` and `DeleteCollection` with an empty collection name.
- `DescribeImport` and `CancelImport` with an empty import ID, and `CreateNamespace` with an empty
  `Name`.
- `ListBackups` with `IndexName` pointing to `""`. Leave `IndexName` nil to list the project's
  backups.
- `ConfigureIndex` with a `ReadCapacity` that sets neither `Dedicated` nor `OnDemand`, which v7 sent
  as a request that changed nothing.

These are plain errors, not a `*PineconeError`.

`ConfigureIndex` with a `Schema` key that isn't the name of the index's semantic text field now
describes the index, then returns a plain error without sending the configure request. The API
accepted such a key and renamed the field to it, so records upserted with the old field name
stopped being embedded. If the describe fails, you get that `*PineconeError` instead.

### The last page of a list has a nil token

When the API sends an empty next token, `ListVectors` and `ListImports` return a nil
`NextPaginationToken`, and the list calls that return a `Pagination` return a nil one. v7 returned a
pointer to `""` from `ListVectors` and `ListImports`, so a paging loop that reads
`*res.NextPaginationToken` without a nil check now panics on the last page:

```go
var token *string
for {
	res, err := idxConnection.ListVectors(ctx, &pinecone.ListVectorsRequest{PaginationToken: token})
	if err != nil {
		log.Fatalf("Failed to list vectors: %v", err)
	}
	for _, id := range res.VectorIds {
		fmt.Println(*id)
	}
	if res.NextPaginationToken == nil {
		break
	}
	token = res.NextPaginationToken
}
```

### An `http://` index host is used as given

An explicit `http://` host in `NewIndexConnParams.Host` is now used as given for document, legacy
Records API, and bulk import calls. v7 rewrote it to `https://` for those REST calls only; vector
and namespace calls over gRPC already used it as given. Such calls go out without TLS, including
the `Api-Key` header. For a Pinecone-hosted index, use the host from `DescribeIndex`, with
`https://` or no scheme; use `http://` only for Pinecone Local or a local proxy. A host with no
scheme still gets `https://`.

### Error text changes

Code should branch on `PineconeError.ErrorCode` and `Code` rather than on message text. If
yours matches text, these messages changed:

- Server messages in a `PineconeError` are no longer HTML-escaped. v7 printed `<`, `>`, and `&` as
  `\u003c`, `\u003e`, and `\u0026`, so `>=` in a server message appeared as `\u003e=`; v8 no
  longer escapes those characters. The JSON in `Msg` decodes to the same values as before,
  except `details`, which is now a JSON object instead of a string in Go syntax.
- When `ConfigureIndex` can't describe the index it was asked to configure (for example, the index
  doesn't exist, or this API version can't represent it), the `"message"` key in `Msg`, and so
  `Error()`, now starts "failed to configure index:" instead of "failed to describe index:", as does
  the new `Message` field. `Code`, `ErrorCode`, `Reason`, and `Details` are unchanged.
- An API error response that has an error code but no top-level `status` field is now parsed. `Msg`
  gains the `"error_code"`, `"message"`, and `"details"` keys, and `ErrorCode` and `Message` are
  set. v7 put only `"status_code"` and `"body"` in `Msg` for such a response.
- Errors the SDK returns before calling the API for options that API version `2026-07` dropped
  (`SourceCollection` and `Schema` on `CreateServerlessIndex`, `Schema` on `CreateBYOCIndex`, `Embed`
  on `ConfigureIndex`, and a pod-based `Deployment` on `CreateIndex` or `CreateIndexFromBackup`) now
  say "Pinecone API versions 2026-07 and later" instead of "Pinecone API version 2026-07".
- The error for an incomplete `ReadCapacity.Dedicated` from the create methods now reads "Dedicated
  read capacity must be configured with a node type, shards, and a scaling strategy (Scaling.Manual
  with Replicas, or Scaling.Auto)". v7 said "... with a node type, scaling strategy, and manual
  scaling configuration". From `ConfigureIndex` on an index with OnDemand read capacity, it now
  starts "the index uses OnDemand read capacity, so it has no current Dedicated settings to keep",
  then names the same three settings.
- The `ConfigureIndex` error for `PodType` or `Replicas` on an index that isn't pod-based now ends
  with "To change the read node replicas of a serverless or BYOC index, set
  ReadCapacity.Dedicated.Scaling".
- Validation errors from `CreateBackup` and `CreateIndexFromBackup` name `CreateBackupParams` and
  `CreateIndexFromBackupParams`, the types you pass, instead of `CreateBackupRequest` and
  `CreateIndexFromBackupRequest`.
- A bulk import error and a plain-text error body now fill `Message`, and `Msg` gains its
  `"message"` key. For a bulk import error, `ErrorCode` and the `"error_code"` key in `Msg` hold the
  gRPC status name, such as `NOT_FOUND`, and `Msg` also gains a `"details"` key holding a JSON list
  when the body's details aren't empty, unlike the object in an API error response. For a
  plain-text body, `Message` holds an excerpt: runs of whitespace become single spaces, and when
  the collapsed text is longer than 512 bytes it is cut at 512 bytes on a UTF-8 boundary and ends
  with "…"; the `"body"` key in `Msg` keeps the full text.
  v7 put only `"status_code"` and `"body"` in `Msg` for both.
- An `AdminClient` OAuth token error now fills `Message`, which starts "failed to get auth token: "
  followed by the token endpoint's description, and sets `ErrorCode` to the OAuth error code, such
  as `access_denied`.
- An admin response the SDK can't decode now returns an error that names the operation, such as
  "failed to decode list projects response: ...", instead of the bare decode error.

### Server errors follow 2026-10

The API returns errors under the `2026-10` rules, as a `*PineconeError`. In particular, a read
capacity change made while another is still being applied, including the initial provisioning right
after create, fails with the error code `ABORTED` and HTTP status 409. Under `2026-07` the same case
returned a 403 status, so v7 code that checked for 403 here should check for `ABORTED` instead.
`RetryPolicy` doesn't retry it.
Branch on the error code rather than the message text, but note that `FORBIDDEN` on a read
capacity request has more than one cause (see
[Replica autoscaling](../index-management/indexes.md#replica-autoscaling)).
`PineconeError.ErrorCode` holds the API's error code, and `PineconeError.Code` the HTTP status.
This loop retries a read capacity change on `ABORTED` and stops on any other error:

```go
params := pinecone.ConfigureIndexParams{
	ReadCapacity: &pinecone.ReadCapacityParams{
		Dedicated: &pinecone.ReadCapacityDedicatedConfig{
			Scaling: &pinecone.ReadCapacityScaling{
				Auto: &pinecone.ReadCapacityAutoScaling{MinReplicas: 1, MaxReplicas: 3},
			},
		},
	},
}
for {
	_, err := pc.ConfigureIndex(ctx, "my-index", params)
	if err == nil {
		break
	}
	var pcErr *pinecone.PineconeError
	if !errors.As(err, &pcErr) || pcErr.ErrorCode != "ABORTED" {
		log.Fatalf("Failed to configure index: %v", err)
	}
	// Another read capacity change is still being applied. Try again once it settles.
	time.Sleep(time.Minute)
}
```

## Deprecated in v8

Both fields still work in v8. Go has no runtime deprecation warning: the field's GoDoc carries a
`Deprecated:` notice, which `gopls` and `staticcheck` (SA1019) report where your code uses it.

| Deprecated | Use instead | Behavior in v8 |
|---|---|---|
| `ReadCapacityManualScaling.Shards` | `ReadCapacityDedicatedConfig.Shards` on requests, `ReadCapacityDedicated.Shards` on responses | Sent as `Shards` when `Shards` is unset; filled in on describe for a manually scaled index |
| `ModelInfo.Modality` | `ModelInfo.Modalities` | Filled from `Modalities`: `"text"` when it includes text, otherwise its only entry; nil when it has several entries and none is text |
