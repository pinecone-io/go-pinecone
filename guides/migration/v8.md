# Migrating to v8 and the 2026-10 Pinecone API

v8 moves the SDK to Pinecone API version `2026-10`, which adds replica autoscaling for dedicated
read capacity. The `X-Pinecone-Api-Version` header is sent as `2026-10` on every request.

For most code, the only change is the import path. Every v7.2.0 call keeps compiling, and nothing
deprecated in v7 is removed.

## Update the import path

```sh
go get github.com/pinecone-io/go-pinecone/v8/pinecone@latest
```

Then replace `go-pinecone/v7/` with `go-pinecone/v8/` in your imports:

```sh
grep -rl 'go-pinecone/v7/' --include='*.go' . | xargs sed -i '' 's#go-pinecone/v7/#go-pinecone/v8/#g'
```

On Linux, use `sed -i` without the empty `''`.

## What's new: replica autoscaling

Set `Scaling.Auto` on `ReadCapacityDedicatedConfig` to let Pinecone move the number of replicas per
shard between `MinReplicas` and `MaxReplicas`. It works on every create method and on
`ConfigureIndex`. See [Replica autoscaling](../index-management/indexes.md#replica-autoscaling).

New in v8, all additions:

- `ReadCapacityDedicatedConfig.Shards` and `ReadCapacityDedicated.Shards`
- `ReadCapacityScaling.Auto` and `ReadCapacityAutoScaling{MinReplicas, MaxReplicas}`
- `ReadCapacityDedicated.ScalingStrategy`, with `ReadCapacityScalingStrategyManual` and
  `ReadCapacityScalingStrategyAuto`

## Behavior changes

These don't change any signature, but code that relies on the old behavior may need an update.

### Describing an autoscaled index

For an autoscaled index, `ReadCapacity.Dedicated.Scaling.Manual` is nil and `Scaling.Auto` holds
the bounds. Code that reads `Scaling.Manual.Replicas` without a nil check panics on such an index,
including one created from the console or another SDK. Check `ScalingStrategy` (a pointer, nil when
the API reports no strategy), or `Scaling.Manual` for nil, first. The live number of replicas per shard is in `Status.CurrentReplicas`.

`ReadCapacity.Dedicated.Scaling` is nil when the SDK doesn't recognize the strategy;
`ScalingStrategy` still reports its name.

### Shards moved out of the manual scaling block

`ReadCapacityManualScaling.Shards` is deprecated. Use `ReadCapacityDedicatedConfig.Shards` on
requests and `ReadCapacityDedicated.Shards` on responses. The old field still works:

- On requests, it's sent as `Shards` when `Shards` isn't set or has the same value. If the two are
  set to different values, both are sent and the API rejects the request.
- When you describe a manually scaled index, it's still filled in.

Before you change `Shards` on a scaling block copied from a describe response, clear
`Scaling.Manual.Shards`, or the request carries both shard counts.

### An empty `Scaling.Manual` block is an error

`ConfigureIndex` with a `Scaling.Manual` block that sets neither `Replicas` nor `Shards` now
returns an error without calling the API. v7 sent `"manual": {}`. API version `2026-10` requires a
replica count with manual scaling, and sending 0 would pause the index. Set `Replicas`, or leave
`Scaling` out to keep the current scaling.

### Server errors follow 2026-10

The API returns errors under the `2026-10` rules, as a `*PineconeError`. In particular, a read
capacity change made while another is still being applied, including the initial provisioning right
after create, fails with the error code `ABORTED`. Under `2026-07` the same case returned a 403
status, so v7 code that checked for 403 here should check for `ABORTED` instead. `RetryPolicy`
doesn't retry it.
Branch on the error code rather than the message text. `PineconeError.Code` holds the HTTP status,
and the error code is in the JSON in `Msg`. This loop retries a read capacity change on `ABORTED`
and stops on any other error:

```go
for {
	_, err := pc.ConfigureIndex(ctx, "my-index", params)
	if err == nil {
		break
	}
	var pcErr *pinecone.PineconeError
	var details struct {
		ErrorCode string `json:"error_code"`
	}
	if !errors.As(err, &pcErr) || json.Unmarshal([]byte(pcErr.Msg.Error()), &details) != nil || details.ErrorCode != "ABORTED" {
		log.Fatalf("Failed to configure index: %v", err)
	}
	// Another read capacity change is still being applied. Try again once it settles.
	time.Sleep(time.Minute)
}
```
